how a timer makes a frequency (from scratch)

a timer is a counter driven by a clock. first the prescaler (PSC) divides the timer clock to make a slower counting clock: it counts PSC+1 input ticks per counter tick (so PSC = 0 means no division). then the counter counts up from 0 to the auto-reload value (ARR) and wraps back to 0, which takes ARR+1 counter ticks. each wrap is an “update event”: it can fire an interrupt, or restart a PWM period.

fout = fclk / ((PSC + 1) · (ARR + 1))

for pwm, ARR+1 is also the number of steps you can divide one period into, so a bigger ARR gives finer duty-cycle resolution. that is why the list prefers a small PSC and a big ARR when several pairs hit the same frequency.

which clock? it is the clock arriving at that timer, not the cpu clock. on most chips, if the apb bus prescaler is not 1, the timer clock is twice the apb clock. check your clock tree in cubemx. this tool assumes edge-aligned (up-counting) mode; center-aligned pwm halves the frequency.

how a usart makes a baud rate (from scratch)

a uart sends bits one at a time at an agreed speed, the baud rate (bits per second). the usart makes it by dividing its input clock with a divider called USARTDIV, which is stored in the baud rate register (BRR) as a number with a few fractional bits. with 16× oversampling the receiver takes 16 samples per bit; with 8× it takes 8, which allows higher baud rates but a coarser divider.

baud = fclk / (oversampling · USARTDIV)

because the divider has limited fractional resolution, the real baud rate is never perfectly exact. the receiver re-syncs at each start bit, so a mismatch of roughly 2% between the two ends is usually fine for 8N1 frames, and beyond about 3% you will see garbage characters.

written for the classic stm32 usart (f0/f1/f3/f4/l0/l1/…). newer series (g0, g4, l4, u5…) add a clock prescaler and lpuart uses a different formula (BRR = 256·fclk/baud), so double-check the reference manual of your chip.
