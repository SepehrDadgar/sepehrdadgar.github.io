# Installing Cadence IC 6.1.7 (Virtuoso) on Bare-Metal Linux in 2026: A Survival Guide

*A practical, no-nonsense walkthrough based on actually doing it on a ThinkPad X201 running Linux Mint 22.1 — through internet shutdowns, missing 32-bit libraries, phantom platform detection, and a simulator that didn't want to be found.*

---

## Why this is hard

Cadence IC 6.1.7 was released around 2015 and officially supported **RHEL 5/6** with **GCC 4.4/4.8**. Modern distros (Ubuntu 24.04, Linux Mint 22.x, Debian 12) have moved on:

- `libncurses5`, `libtinfo5`, and `libxp6` are gone.
- `libdl.so` is merged into libc.
- `/etc/os-release` looks nothing like Red Hat's.
- OpenAccess refuses to configure itself on an unrecognized platform.
- Bundled `libstdc++.so.6` is older than what your system's GL libraries require.

None of this is fatal. It's just a lot of small patches. Here's the full recipe.

---

## What you need

- A machine running a modern Debian/Ubuntu-family distro (tested on **Linux Mint 22.1**, Ubuntu 24.04 base).
- ~30 GB free disk space.
- The Cadence IC 06.17.700 installer files (`IScape04.23-s010lnx86.t`, `IC06.17.700_Base/`).
- Optionally: MMSIM 15.10.257 (Spectre) as a separate install.
- Optionally: A TSMC 65nm PDK.
- Root access (sudo).
- Patience. An internet connection that works *some* of the time.

## Step 1: System prerequisites

Modern Ubuntu/Mint has dropped a lot of 32-bit and legacy libraries Cadence needs. Install them now:

```bash
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install ksh csh libc6:i386 libstdc++6:i386 libx11-6:i386 \
  libxext6:i386 libxtst6:i386 libxi6:i386 libxrender1:i386 \
  libxt6t64:i386 libelf1t64:i386 libxft2:i386 libxcursor1:i386 \
  lib32z1 openjdk-8-jre xfonts-100dpi xfonts-75dpi mawk
```

### The libraries that no longer exist

`libncurses5:i386`, `libtinfo5:i386`, and `libxp6:i386` are gone from Ubuntu 24.04. You have to fetch them from Ubuntu 22.04 (jammy) or older. Two approaches:

**If your mirror still has jammy pool access**, download the `.deb`s directly:

```bash
# From AminIDC (Iran) or any Ubuntu mirror
wget http://mirror.aminidc.com/ubuntu/pool/main/n/ncurses/libncurses5_6.1-1ubuntu1_i386.deb
wget http://mirror.aminidc.com/ubuntu/pool/main/n/ncurses/libtinfo5_6.1-1ubuntu1_i386.deb
wget http://mirror.aminidc.com/ubuntu/pool/main/libx/libxp/libxp6_1.0.2-1ubuntu1_i386.deb

sudo dpkg -i libtinfo5_*_i386.deb libncurses5_*_i386.deb
```

For `libxp6`, the `multiarch-support` pre-dependency no longer exists, so you have to force it and then work around the dependency:

```bash
# Extract manually instead of installing
dpkg-deb -x libxp6_1.0.2-1ubuntu1_i386.deb /tmp/libxp
sudo cp /tmp/libxp/usr/lib/i386-linux-gnu/libXp.so.6* /usr/lib/i386-linux-gnu/
sudo ldconfig
```

Verify:

```bash
ldconfig -p | grep libXp
```

### Missing symlinks that break older binaries

Ubuntu no longer ships unversioned `.so` files for several libraries. Cadence binaries look for them:

```bash
sudo ln -sf /usr/lib/x86_64-linux-gnu/libdl.so.2 /usr/lib/x86_64-linux-gnu/libdl.so
sudo ln -sf /lib/x86_64-linux-gnu/libncursesw.so.5 /lib/libtermcap.so.2
sudo ln -sf /usr/bin/mawk /bin/awk
```

## Step 2: Extract and install IC 6.1.7

Move the installer out of any path containing **spaces** — this alone causes half the InstallScape failures people hit.

```bash
mkdir -p ~/cadence/installs
cd ~/cadence/installs

# Extract the InstallScape archive (it's a plain tar, not gzip)
tar xvf /path/to/IScape04.23-s010lnx86.t

# It creates a folder like iscape.04.23-s010
mv iscape.04.23-s010 ~/iscape
```

Launch the installer:

```bash
cd ~/iscape/bin
./iscape.sh
```

In the GUI:

1. **Preferences → Directories**
   - Default Install Directory: `~/cadence/installs/IC617`
   - Cache Directory: `~/cadence`
2. **File → Install from Local Directory**
   - Browse to the **parent** of `IC06.17.700_Base` (not inside it).
   - Select IC06.17.700 from the detected products.
3. Choose your products (at minimum: Virtuoso Schematic Editor, Virtuoso Layout Suite, ADE L/XL, Spectre if installing MMSIM separately).
4. Install.

The installer will unpack hundreds of `.t.Z` kits. Take a coffee break.

## Step 3: Make OpenAccess accept your platform

When you first run `virtuoso`, you'll hit:

```
ERROR: The OA2.2 library directory (.../linux_rhel60_gcc44x_64/opt) does not seem to exist.
```

**Why:** OpenAccess's `sysname` script doesn't recognize Linux Mint, so it returns `unknown`. But your installation *does* ship binaries for `linux_rhel50_gcc48x` — you saw those in `share/oa/bin/`.

**Fix:** Replace the `sysname` script with a hardcoded one matching the binaries you actually have.

```bash
cd ~/cadence/installs/IC617/share/oa/bin
mv sysname sysname.bak
cat > sysname << 'EOF'
#!/bin/bash
echo "linux_rhel50_gcc48x"
EOF
chmod +x sysname
```

Verify:

```bash
./sysname   # should print linux_rhel50_gcc48x
```

**Bonus:** If you also want `checkSysConf` to pass, temporarily spoof `/etc/os-release` as RHEL 6, run the check, then restore it. Not required for the tools to run.

## Step 4: Deal with the bundled libstdc++

The first successful launch of `virtuoso` might fail with:

```
version `CXXABI_1.3.8' not found (required by /lib/x86_64-linux-gnu/libGLU.so.1)
```

Cadence bundles an old `libstdc++.so.6` that shadows your system's newer one. Move it aside:

```bash
cd ~/cadence/installs/IC617/tools/lib/64bit
mv libstdc++.so.6 libstdc++.so.6.cadence_old
```

Your system's `/usr/lib/x86_64-linux-gnu/libstdc++.so.6` will now be used. This is safe — the Cadence tools themselves are compiled against the C++ ABI your system provides.

## Step 5: Environment setup

Add to `~/.bashrc`:

```bash
export CDS_ROOT=/home/$USER/cadence/installs/IC617
export CDS_INST_DIR=$CDS_ROOT
export CDSHOME=$CDS_ROOT
export CDSROOT=$CDS_ROOT
export PATH=$CDS_ROOT/tools/bin:$CDS_ROOT/tools/dfII/bin:$PATH
export LM_LICENSE_FILE=/home/$USER/cadence/license/license.dat
export CDS_LIC_FILE=$LM_LICENSE_FILE
export CDS_LIC_ONLY=1
export CDS_AUTO_64BIT=ALL
export LANG=C
export CDS_Netlisting_Mode=Analog
export CDS_LOAD_ENV=CWD
export OA_SYSTEM_NAME=linux_rhel50_gcc48x
```

Reload:

```bash
source ~/.bashrc
```

Now `virtuoso &` should launch.

## Step 6: Installing Spectre (MMSIM) separately

**Key realization:** MMSIM (the Spectre simulator) is a **separate installation** from IC617. You won't find `spectre` anywhere inside your IC617 tree — that's expected.

Extract MMSIM's own InstallScape and install to a sibling directory:

```bash
cd ~/cadence/installs/MMSIM15
tar xvf IScape04.23-s010lnx86.t
mv iscape.04.23-s010 ~/iscape_mmsim
cd ~/iscape_mmsim/bin
./iscape.sh
```

Install to `~/cadence/installs/MMSIM151`, then add to `~/.bashrc`:

```bash
export MMSIM_HOME=/home/$USER/cadence/installs/MMSIM151
export PATH=$MMSIM_HOME/tools.lnx86/bin:$MMSIM_HOME/tools.lnx86/spectre/bin/64bit:$PATH
export SPECTRE_FEATURE_FILE=$MMSIM_HOME/tools.lnx86/spectre/etc/files/spectre.dat
```

Note the `tools.lnx86` — Cadence's older naming. The 64-bit spectre binary lives under `tools.lnx86/spectre/bin/64bit/`.

### Apply the same fixes to MMSIM

Find and patch the `sysname` script inside MMSIM too (it will be somewhere under `MMSIM151/tools.lnx86/spectre/`). Move MMSIM's bundled `libstdc++.so.6` aside as well. Same errors, same fixes.

Verify:

```bash
which spectre
spectre -h    # prints version banner
```

## Step 8: Installing the TSMC 65nm PDK
as an example
The PDK comes with a Perl installer:

```bash
cd ~/Downloads/TN65CMSP007K3_1_7A
perl pdkInstall.pl
```

You'll be asked three questions:
- **Process type:** `1` (LO / Logic) is sufficient for most analog/digital work.
- **Voltage:** `1` (1.2V / 2.5V / under-drive 1.8V / over-drive 3.3V) — the most flexible.
- **Metal option:** `1` (`1p9m_6X2Z0U_ALRDL`) — 9 metal layers, best for routing.

Do **not** try to install all combinations at once — it's 48 permutations and takes forever. Start with one.

After installation, set up your project:

```bash
mkdir -p ~/cadence_projects/my_design
cd ~/cadence_projects/my_design
cat > cds.lib << EOF
DEFINE tsmcN65 /home/$USER/cadence/installs/TN65CMSP007K3_1_7A/tsmcN65
DEFINE myLib ./myLib
EOF
cp ~/cadence/installs/TN65CMSP007K3_1_7A/display.drf .
```

**Do not** use relative paths like `./tsmcN65` unless the PDK folder is literally inside your project — that's a common source of "library not found" warnings.

### Attaching your library to the PDK tech

When you create a new library in `myLib`, attach it to the `tsmcN65` technology. If you forget, you'll see a warning on startup but everything else works — just attach it via the Library Manager properties.

## Step 9: Desktop shortcut

A `.desktop` file that sources your env and launches from the right directory:

```bash
cat > ~/bin/virtuoso_tsmc65.sh << 'EOF'
#!/bin/bash
source ~/.bashrc
cd /home/$USER/cadence/installs/TN65CMSP007K3_1_7A
virtuoso &
EOF
chmod +x ~/bin/virtuoso_tsmc65.sh
```

Then `~/Desktop/Virtuoso_TSMC65.desktop`:

```ini
[Desktop Entry]
Version=1.0
Type=Application
Name=Virtuoso TSMC65
Comment=Launch Virtuoso with TSMC 65nm PDK
Icon=system-run
Terminal=false
Exec=/home/YOUR_USER/bin/virtuoso_tsmc65.sh
Categories=Development;Electronics;
```

Mark it executable and trusted:

```bash
chmod +x ~/Desktop/Virtuoso_TSMC65.desktop
gio set ~/Desktop/Virtuoso_TSMC65.desktop metadata::trusted true
```

Don't put `&` in the Exec line of the `.desktop` file itself — put it in the script.

## Step 10: Optional — Synopsys HSPICE integration

If you have a licensed HSPICE install, Cadence's `hspiceD.cxt` interface will try to find it at a hardcoded path like `/opt/synopsys/Hspice-2015.06-3`. If your install is elsewhere, symlink it:

```bash
sudo mkdir -p /opt
sudo ln -sf /home/$USER/cadence/installs/synopsys /opt/synopsys
```

Set the license variable in `~/.bashrc`:

```bash
export HSPICE_HOME=/opt/synopsys/Hspice-2015.06-3/hspice
export SNPSLMD_LICENSE_FILE=/path/to/synopsys/license.dat
```

The CIW log should then show:

```
HSPICE-ADE: use HSPICE at '/opt/synopsys/Hspice-2015.06-3/hspice/bin/hspice'
```

If you don't have an HSPICE license, ignore this section entirely. Spectre is fully sufficient for analog simulation.

## Summary of the non-obvious gotchas

| Problem | Fix |
|---|---|
| InstallScape can't find products | Path contains spaces; move the installer |
| `sysname returned unknown` | Replace `sysname` with `echo linux_rhel50_gcc48x` |
| `CXXABI_1.3.8 not found` | Move bundled `libstdc++.so.6` aside |
| `libdl.so: cannot open` | Symlink `libdl.so.2` → `libdl.so` |
| `libncurses5`/`libtinfo5`/`libxp6` missing | Manually install from jammy pool |
| Spectre not found anywhere in IC617 | It's a **separate** MMSIM install |
| Flat line in ADE | Set source's **AC magnitude = 1** |
| Library warnings on startup | Use absolute paths in `cds.lib` |
| Desktop file doesn't launch | Use a wrapper script, not a shell one-liner |

## A note on internet shutdowns

If you're working through a national internet shutdown (this guide was written during one 😢FML)(done during the internet shutdown after the January 8th and 9th uprising in Iran), your best options are:

- **Local mirrors** (like AminIDC in Iran, `mirror.aminidc.com`).
- **Direct `.deb` downloads** from the pool, bypassing broken i386 indexes.
- **Manual symlinks** where packages are genuinely gone.

The apt "Unable to locate package" error when a mirror lacks i386 indexes doesn't mean the package doesn't exist — it means the *index* is missing. Go to the pool directory and fetch the file directly.

## Final thoughts

Installing a decade-old EDA suite on a modern distro is fundamentally an archaeology exercise. Every missing library, every spoofed platform name, every symlink is a patch over a 10-year gap between when the software was written and when you're running it.

But it *does* work. Once you get past the initial setup — maybe 2-3 hours if you hit all the snags I did — you have a fully functional analog design environment: schematic capture, simulation, layout, PDK, the works. On a 2010 ThinkPad, no less.

Welcome to the other side.
